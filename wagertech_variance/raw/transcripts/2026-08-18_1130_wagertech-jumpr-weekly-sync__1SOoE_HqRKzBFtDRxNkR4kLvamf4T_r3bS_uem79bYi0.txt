Summary
The team defined integration protocols, structured brand ambassador records, and established standardized player and referrer statuses.

System Integration and Testing
Testing utilizes live data to prioritize volume analysis while shifting deduplication logic to a person account model. The group decided to implement API keys and IP whitelisting for integration security.

Ambassador Data Model Design
Reporting structures depend on standard manager fields, and unnecessary data fields like verticals are removed to streamline records. Standardized ambassador statuses facilitate consistent operational reviews.

Status and Referral Definitions
Player and referrer statuses trigger internal flagging after 90 days of inactivity. Referral records reside exclusively within the sales platform to maintain data integrity.


Decisions
Aligned
* Sandbox data designated as throwaway The team designates all data pushed to the sandbox environment as throwaway data for the duration of the API testing phase.
* Salesforce deduplication logic disabled The Salesforce integration will refrain from implementing internal deduplication logic, relying instead on the source system to send clean, deduplicated data for processing.
* Test deals effective start date All test deals are effectively activated as of today's date for the purpose of integration testing.
* Unconfigured agent data handling Incoming data for agents not yet configured in the system will be flagged for review rather than creating signup records.
* API integration launch target The go-live target for initial API integration testing is scheduled for Thursday.
* Slack-based error notification implementation A Slack connector will be implemented to provide real-time visibility into errors surfacing from the queue.
* CMS-side API endpoint architecture Integration architecture is set to build an API endpoint on the CMS side for Salesforce to call, rather than establishing a Salesforce-initiated connection.
* API endpoint security configuration The API endpoint security strategy is finalized as IP whitelisting combined with API keys.
* Manual Salesforce rep administration Rep account creation and permission management will be conducted as a manual administrative task in Salesforce rather than via automated CMS integration.
* Brand Ambassador status definitions Brand Ambassador status definitions are set to: active, paused, inactive, and terminated.
* Standard Salesforce hierarchy adoption The standard Salesforce out-of-the-box manager field and user hierarchy will be utilized for managing Brand Ambassador and Manager relationships.
* Secondary market tracking method Secondary market tracking will utilize multi-select picklists to accommodate multiple market assignments per Brand Ambassador.
* Automation added for termination tracking The system will include an automation to track the termination date for users.
* Unnecessary BA fields removed The 'payment method', 'preferred contact method', and 'payment frequency' fields will be removed from the Brand Ambassador records.
* Login and contact email fields separated Separate fields will be created for the login username, primary email, and transfer email to ensure distinct data storage.
* Verticals field removed The 'verticals' field will be removed from the Brand Ambassador record.
* Landing page field renamed The 'landing page' field will be renamed to 'agency site' and retained alongside slug and external ID fields.
* Copy functionality excluded from launch Custom copy-paste functionality will not be implemented for launch, relying on standard text selection instead.
* Player currency defaulting logic established Player record currency will default to the currency of the first associated signup.
* Manual VIP toggle implemented A manual VIP toggle restricted to authorized users will be implemented for player records.
* BA attribution mismatch flagging implemented Signups and Clicks (SLC) where the assigned BA does not match the player's BA will be flagged for manual Ops review.
* Survey completion field removed The 'survey completion' field will be removed from the record.
* Player inactive status threshold set Player inactive status will trigger automatically after 90 days of inactivity.
* Banned player status visual indicator Banned player status will be indicated via a top-level banner rather than specific restriction fields.
* Referrer inactive status threshold set Referrer inactive status will trigger automatically after 6 months of inactivity.
* Flagging strategy for restricted referrers Signups from paused or banned referrers will not be blocked, but flagged for Ops review.
* Payout preference moved to notes The 'payout preference' field will be moved to a general notes section at the bottom of the record.
* Email-based referrer deduplication Email-based deduplication will be implemented for referrers, blocking the creation of duplicate records.


Shelved
* Storage proofs development shelved The development of storage proofs is deprioritized and shelved in favor of focusing on deal configuration tasks.
* Prevel status field removed The 'Prevel status' field will not be included in the current development scope.
