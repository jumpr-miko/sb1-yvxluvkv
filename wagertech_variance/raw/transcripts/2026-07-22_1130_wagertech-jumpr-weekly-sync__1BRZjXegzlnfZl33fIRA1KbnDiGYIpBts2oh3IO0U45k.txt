Summary
Meeting discussions focused on Salesforce interface architecture, workflow status definitions, and technical integration strategies for automation.

Salesforce Interface and Design
The team prioritized standard interface elements to preserve timelines and maintenance costs. They decided to implement a read-only banner for signups and display specific data in the header.

Workflow and Status Logic
Participants aligned on a status path of New, In Progress, and Completed. They agreed to split the Flagged category into Fraud and Archived to ensure accurate tracking.

Integration and Optimization
Salesforce will serve as the primary management system for CMS data integration. The team also agreed to adopt the Salesforce mobile application for native accessibility.


Decisions
Aligned
* Click history moved to separate tab The click history section will be moved to a separate tab, and the attribution and player information will be placed in the details section to optimize the layout.
* Read-only banner added to UI A banner will be added to the top of the UI to clearly indicate when fields are read-only for users.
* Emoji usage for status representation Emojis will be implemented for displaying visual status representations, such as country flags or status indicators, rather than relying solely on text.
* Phase one UI customization limitations The team will prioritize out-of-the-box Salesforce functionality over extensive LWC customization for Phase 1 to manage maintenance costs and project timelines.
* List view renamed to In Progress The "Q" list view will be renamed to "In Progress" to better align with the signup status.
* Signup page field display adjustments The "Brand Ambassador" field will be removed from the UI, and the "Operator" and "Partner" information will be consolidated or displayed simply as "Operator" to simplify the interface.
* Header section field placement Vertical and market information will be moved to the header/highlight section of the interface for improved visibility.
* Re-introduction of linear status path The linear path displaying "New," "In Progress," and "Completed" statuses will be re-introduced to the user interface.
* Fraud and completion status handling Fraud detection and flagged statuses will be tracked via a separate field or sub-status rather than being part of the primary linear status path, allowing for completion status to remain intact while flagged.
* Inclusion of archived status "Archived" will be implemented as a status to allow for the removal of stagnant or inactive signups from the active "In Progress" queue.
* Archiving and Fraud status structure The system will implement separate 'Archived' and 'Fraud' statuses, removing the 'Flagged' category and providing unique reason lists for each.
* UI cleanup via information layering The UI cleanup strategy will involve moving non-essential fields into 'More Info' sections rather than removing them from the system, to maintain data availability while simplifying the interface.
* Operator and Partner display logic The Q list view for representatives will display only the Operator, while the Ops view will continue to display both the Operator and the Partner.
* Deal assignment status visual indicators The deal assignment screen will include visual status indicators, such as colors and emojis, to denote states like active or paused assignments.
* Salesforce to CMS integration direction Salesforce will serve as the source of truth for deal assignments, pushing relevant data to the CMS via an API endpoint.
* User input date format simplification Time components will be removed from all user-inputted Date fields, while system-generated timestamps will retain time accuracy.
